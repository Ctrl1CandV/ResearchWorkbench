# DESIGN-REWORK-007：设计问题根因分析与重构方案（2026-09-21）

来源：2026-09-20/21 两轮实页视觉评审（1280×720 与 390 视口截图 + DOM 测量）。
用户 2026-09-21 裁决：问题成立，本轮从批评转入根治；同时裁决 D4（BACKLOG 第 7 项）——
**"或/与"口径矛盾不再纠结，内容库已膨胀，直接拆分**。本文档记录根因链、方案与验收；
实现与测试同轮落地，本文档与代码不符时以代码与测试结果为准并回改本文档。

## 0. 总根因（两条，覆盖全部五个问题）

1. **界面按"平台有哪些模块"组织，不按"我今天来做什么"组织。**
   每个新功能上线时都"追加到最合适的位置"（面板放顶上便于发现、发现区放简报上方因为它是
   新接通的能力），从未按高频使用者的路径回头排优先级。SPEC 只约束了各区的存在与真实性
   （PF-01"各区均有真实预览、用途和入口"），没有约束顺序与时间性，于是默认位置固化成契约。
2. **内容生产纪律被平铺成视觉元素，而不是折叠成一次性视觉约定。**
   三条轴、四档深度、不冒充已读——这些是正确的数据纪律，但渲染层把每条纪律在每一屏都用
   同等权重的视觉件（chip、虚线框、灰字段）重申一遍，徽章与免责因此线性增殖。诚实口径的
   正确形态是：全站约定讲一次（页脚"关于内容与来源"），每卡用统一的最小记号表达。

改版约束（用户 2026-09-18 既有裁决，继续有效）：不新增视觉板块、优先文本层方案、
不动 CSS 结构性的东西只删装饰、不借机重排已批准内容。

## 1. 辅助件压在内容之上

**现象**：论文页"我的记录"表单位于标题与正文之间（实测 1280 下正文首节 y=953；390 下标题
y=701）；每日精选页"近期登记发现"大面板排在唯一每日变化的选编简报之上。

**根因链**：`library.js` renderPaper 中 `article.appendChild(renderNotesPanel(paper))` 紧跟
paperHeader（原 1883 行）；`renderBrief` 中 `page.appendChild(renderDiscoverSection())` 在
简报面板之前（原 2264 行）。两处都是 PLAN-005 功能落地时"新能力放最显眼处"的一次性决策；
SPEC/DESIGN 无位置条款，测试只断言"存在"（render.test v3 用例只查 `textContent.includes`），
没有任何机制要求记录面板服务于阅读动线而非抢占它。

**方案**：
- 论文页：记录面板移到正文全部章节与"下一篇"之后、"来源与覆盖"之前——记录是读完后的动作。
- 精选页：发现区移到当期简报与历史索引之后。页面结构顺序即优先级：简报 → 历史 → 发现。
- 测试补位置断言（正文先于面板），DESIGN.md 记录"阅读动线优先于功能入口"。

## 2. 首页无时间锚点

**现象**：首屏是四区功能自述 + 永久"建议先读" + 过期顶栏日期（"2026-09-15"）；
"每日精选"排第四区；DESIGN.md 自己写的"首页突出第一篇推荐，而非同权重卡片网格"未落地。

**根因链**：PF-01 把首页定位为五区导览页——这是为**首访**设计的，从未为**每日回访**设计。
平台其实有合法的时间信号（briefs 最新期、v3 本人"在读"标记），但：① 防"伪造个人进度"
的禁令（"不出现任何本人进度"）被理解为首页完全不能引用 v3 数据，而真实的本人标记不是伪造；
② zone 渲染顺序硬编码在 renderHome，briefs 是后加区所以排后面。

**方案（全部文本层，不新增板块）**：
- 顶部更新行并入时间信号："内容更新日期 …；最新简报 2026-09-18（缺日即当日未产出）"。
- 区序改为：每日精选 → 论文阅读 → 方向与路线 → 技术学习 → 经典书目（数据 zones 数组同序，
  library.test 顺序断言随之更新）。
- 论文阅读区顶部：当 v3 存在"在读"标记时显示一行"我在读（本人标记）：《…》《…》"链接；
  无标记时维持"建议先读"卡。这不是进度统计，只是本人标记的直达——SPEC PF-01 措辞相应
  补一句"本人手动标记的在读条目可作直达入口出现，不构成进度认定"。
- 首页"建议先读"卡内两个按钮（打开阅读卡/全部论文）降为普通链接，绿色大按钮只保留在
  真正需要动作确认处（保存记录）。

## 3. 徽章墙

**现象**：论文列表 45 条目 × 5 chip = 166 枚圆角标签；"原文入口 · 未获取摘要，不是阅读卡"
整句塞进一个 chip。

**根因链**：三条轴 + role + 深度共五个独立维度在数据层各自成立（这是 READING-TEMPLATES-005 §1
的核心设计，不能砍维度），渲染层用同一个 `lib-badge` chip 模板表达一切"标签短语"，且
DEPTH_LABELS.entry 的长句（它本来是为论文页页眉的诚实标注写的）被列表页无差别复用。
chip 的边框 + 底色让每条记录获得五块等权重噪声，全部同色 = 没有层级。

**方案**：
- `paperBadges()` 数据函数保留（测试锁定，语义不变）；**渲染改为纯文本 meta 行**，
  " · " 连接，复用既有 `.lib-depth-note` 灰字样式；chip CSS（.lib-badge/.lib-badge-kind/
  .lib-badges）删除。
- 列表页 entry 深度用短标签"原文入口"；完整句"原文入口 · 未获取摘要，不是阅读卡"只在
  论文页页眉出现（诚实标注不丢，位置从 166 处收敛到它该在的地方）。
- 路线步骤的双 chip（.lib-flag：必读/深度）同改纯文本行。

## 4. 免责声明四层重复

**现象**：全站横幅 + 页面说明段 + 虚线提示框 + 卡末句四层讲同一件事；列表页 6805 字内
此类句式 29 处，真正的边界信息（asOf、来源"作者全文"vs"只依据摘要"）被同等灰字稀释。

**根因链**：诚实纪律按视图各自实现：每个 renderer 自守一句（renderPapers intro、quick/entry
卡 notice、discover 段、archive 注脚、renderComparison 表注），meta.notices 又整批重复其中
一部分。没有"分层职责"约定：哪层管全站、哪层管单卡。

**方案（分层收敛，纪律数据一条不删）**：
- 页脚"关于内容与来源"= 全站唯一详述层（不动，测试锁定 notices 原文）。
- 页面级说明 = 各页顶部一段（papers/foundations/brief 现有，保留，各页只讲一次）。
- 卡级 = 一行短句：quick 卡改"本篇判断只依据摘要，正文未读；依据与未核对部分见下方
  '来源与覆盖'。"；entry 卡改"未获取到可靠摘要；这里只有论文身份与入口，不含内容判断。"
  样式从虚线框（.lib-notice-flat）降为普通灰字（.lib-depth-note）——记号收敛本身减负一层。
- discover 面板说明段砍半（结果区本来就有 registrationNote/topicFilterNote 兜底）。
- 表格注、archive 注等"位置专属提醒"保留（它们各自防的是不同误读）。

## 5. 为设计而设计的装饰

**现象与根因**：
- 技术路线卡标题绿 + 下划线：其它标题链接类（.lib-paper-title a、.lib-step-title a）都有
  `text-decoration:none` 覆盖，`.lib-tech-title a` 是模式化遗漏，导致唯一"标题长得像正文
  链接"。→ 补同一规则。
- 编号圆圈 + 竖线（.lib-steps ::before/::after）：为"可感知的顺序"造的重装饰；顺序感实际由
  文字（"第二篇，紧接 TOSEM"）承载。→ 圆圈底色与圆形降为纯数字，连接线保留。
- 首页五区角链接（"查看三个方向"等）与区体内容重复：PF-01 要求各区有"真实入口"，保留角
  链接但接受其弱存在；真正删的是首页卡内按钮（见 §2）。
- 阶段 chip（.lib-stage-label）：一页最多四个，是唯一的阶段锚点，**保留**——不是所有标签
  都是徽章墙。

## 6. 内容库拆分（BACKLOG 第 7 项，用户 2026-09-21 裁决执行）

**膨胀根因**：PLAN-005 为"避免两份长期手改"确立单一公开内容源，此后一切追加都进同一数组；
同时 server.mjs 固定白名单使新增可服务文件需要同时改 ROUTE_MAP + 两处白名单测试，
新文件边际成本高，拆分长期被推迟。D4"或/与"口径矛盾只是表象，真阻力是这个三处联动。
现 45 篇 ≈ 210KB、3396 行，两个口径都已越线。

**拆分设计**（保持 `LIBRARY` 聚合导出与既有全部测试入口不变）：
- `public/content/directions.js` → DIRECTIONS（3 方向含路线）
- `public/content/papers-routes.js` → ROUTE_PAPERS（方向一/二/三正文卡组）
- `public/content/papers-supplements.js` → SUPPLEMENT_PAPERS（旧版支线 + 三方向补充）
- `public/content/papers-foundations.js` → FOUNDATION_PAPERS（经典 11 篇）
- `public/content/technical-routes.js` → TECHNICAL_ROUTES（11 条）
- `public/content/briefs.js` → BRIEFS（4 期）
- `public/library-content.js` 收缩为聚合器：contentVersion + meta + home + foundations 配置 +
  按原序拼接 `papers: [...ROUTE_PAPERS, ...SUPPLEMENT_PAPERS, ...FOUNDATION_PAPERS]`。
  **数组顺序与拆分前逐元素一致**（"事实字段与基线一致"测试锁定顺序，拼接序即原分组序）。
- server.mjs ROUTE_MAP 增六条精确路径；两处白名单测试同步（哨兵文件需建子目录）。
- 拆分时顺带修复：`brief-2026-09-15` 对象内**重复 `scope:` 键**——2026-09-18 统一三段式时
  新文本插在旧文本上方而未删旧行，JS 后者覆盖，页面实际显示的是旧的非三段式文案，与
  HISTORY"四期 scope 已统一"记录不符。删除旧键保留三段式（其内容满足测试锁定的
  /不是当天的穷尽检索/、/429\/503/、/不能把"今天没有新论文"…/ 三个断言）。

## 7. 本轮验收标准

1. `npm test` 全绿（基线 123 项 + 新增位置/时序断言；条件跳过符号链接 1 项允许）。
2. 实页复核（1280 与 390）：论文页正文先于记录面板；精选页简报先于发现区；首页首现区为
   每日精选；列表无 chip；技术路线标题无下划线。
3. 内容零漂移：papers 顺序/条数/字段逐字节等价于拆分前（git diff 审查 + 基线测试）。
4. 文档同步：SPEC（PF-01 补句、当前状态、文档地图）、DESIGN（动线/记号约定）、
   BACKLOG（第 7 项闭合、新增视觉矩阵缺口更新）、README（项目结构）。
5. 不提交、不推送（待用户授权）。
