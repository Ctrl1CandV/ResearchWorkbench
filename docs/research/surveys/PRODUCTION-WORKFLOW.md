# 综述阅读包：重复生产流程

这里记录本工作台静态内容阶段实际采用的轻量流程。网站不会假装提供自动论文检索或 PDF 阅读 Agent；生产由用户选择的 harness 中的 Agent 完成，经过人工核对后更新 `public/content/surveys.js`。

## 1. 确认输入与范围

输入可以是领域、关键词或指定文章。先明确当前任务是宽领域起步地图还是处理一篇指定综述。用户指定本机材料时，优先尊重其来源与隐私要求；没有获得联网授权时不外部搜索。一般新主题控制为一篇主读加至多两篇互补候选，并解释互补点与边界。

## 2. 固定论文身份和版本

从论文首页、正式出版信息或稳定标识符确认标题、作者、来源、年份、DOI/arXiv ID、PDF 页数。记录原始文件名、版本说明和 SHA-256。正式版和预印本不得混合章节号、页码、图号和结论。PDF 留在原位置，不提交、不把个人绝对路径写入发布数据。默认不向第三方上传；如果确需云解析，必须事先明确获准上传的是哪份材料、发送给哪项服务及用途。按页选择通常只限制解析输出，并不表示只上传了那些页面；应在 manifest 中如实记录上传范围、服务、日期、页范围、任务标识与返回产物。向 MinerU 上传须有明确授权。三篇公开综述（ACL 2026、FCS 2024、arXiv 2023 v3）均曾在获准后提交完整 PDF；页码参数只限制解析输出。不能据此推定私人或未发表材料也获准上传。

## 3. 获取结构与逐项清点

提取全文文字只作为导航；逐章检查正文、关键图表、公式、脚注和必要附录。建立目录清单，逐项标记：

- `taught`：已阅读并映射到讲解单元；
- `reference-only`：作为引文/检索索引，不逐篇讲解，必须解释边界；
- `missing`：缺全文或材料，说明原因并阻止完整状态。

caption 可读而图不可读时记录 `caption-only`，不可把它算作图表核验。不同页码体系要同时注明 PDF 页与正式出版页。

## 4. 形成阅读稿

先写文章概览，再按认知结构组织单元。每段以连贯解释为主，覆盖术语、分类依据、机制、代表例子、比较条件、反例/限制以及与邻节关系。卡片只作为导航入口，不设统一字数上限。引用中的原始研究需标为“综述转述”，除非确实另行读取原论文。

发布正文采用安全 DOM 渲染，block 支持 `heading`、`paragraph`、`comparison`；讲解来源角色区分 `source-explanation`、`teaching-example` 与 `editorial-connection`，章节标题使用 `section-heading`。交互图以数据生成 SVG，图轴/节点解释、定位与可选正文锚点须经校验；不直接注入任意 HTML/SVG。source-explanation 必须附 PDF 页、章节或图表定位。

## 5. 建图并安排读序

作者目录按原文标题/顺序展示；单元语义关系说明“为何连接”；推荐读序标为编辑安排。文章内整篇图必须覆盖每个已制作的阅读单元，分组折叠不能删除单元或正文；候选文献不生成空壳图。文章间关系需写明 relation 类型、理由和两端阅读单元。共同引用不等于彼此引用；“互补”不自动表示先修；没有可靠关联依据就不连边。

## 6. 内容复核和状态

制作人逐条对照原文检查核心定义、比较、数字、否定发现、条件及图表解释。其次检查单元覆盖是否能从完整目录追溯。`candidate` 表示只有来源；`partial` 表示覆盖/视觉/版本尚有缺项；`complete` 只用于正文与必要附录均有清楚处置、关键图表已视觉确认、引用定位一致且没有未解决来源问题的阅读包。结构校验不能替代内容复核。

## 7. 发布与页面

先运行 `npm run validate:surveys`。从书架打开概览，检查来源版本、目录映射、关系理由和未完成项；进入阅读单元检查解释、表格、引用与上一页/下一页入口。来源位置以文件名+PDF 页/文章节标识，避免产品打开任意本机文件路径。
