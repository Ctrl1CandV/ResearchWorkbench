## 对组件框架的理解

- Profile：描述身份/角色、目标及与任务相关的属性；人工设定、模型生成和数据对齐对应不同来源，不能把 prompt 设定说成模型实际具有某种稳定人格。
- Memory：结构、格式和操作是不同维度。自然语言可解释且语义丰富，embedding 便于检索；读取、写入、遗忘/覆盖和反思都有独立设计取舍。
- Planning：单路径、并行候选/搜索、外部规划器、环境反馈和人类反馈，复杂程度及可验证性各不相同。
- Action：既包括外部工具，也涉及 LLM 内部知识；行动可能改变环境状态，因而需要后续观察与计划调整。
- Capability acquisition：监督微调属于训练路径；提示、检索工具、反馈与多 Agent 讨论属于不同的系统/推理路径，不应混称为权重学习。

## 评价与限制

主观方法可以覆盖用户体验或社会属性，但依赖人类量表和参与者；客观方法适合任务结果、工具执行或测试覆盖，却受任务定义和指标覆盖范围限制。作者列出的角色模拟、对齐、prompt 鲁棒性、幻觉、知识边界和效率问题相互影响。文章覆盖面广，是概念入口；对 2024 年后的工具与评价变化没有覆盖，也没有专门评测跨 harness 通信。

新增阅读单元将 Memory 拆成三个可组合而非互斥的分析轴：

- **结构**：统一记忆通常把当前需要的信息放入 prompt/context；混合结构让短期缓冲与外部长期保存并行。统一结构直接但受上下文长度限制；混合结构能积累长期经验，同时引入何时写入、取回哪段和相关性是否可靠的问题。作者还说明单独长期记忆在其考察文献中少见，并把短期状态的重要性作为对动态连续任务的解释/推测，而非普遍定律。
- **表示形式**：自然语言、embedding、数据库和结构化列表分别支持可读表达、相似检索、精确操作与显式组织；可以组合使用。GITM 例子中 key 用向量帮助匹配，value 用自然语言保留信息，说明“向量还是文本”不是二选一。
- **操作**：读取综合近期性、相关性、重要性；写入要区别重复合并和容量溢出；反思把若干经历归纳成高层 insight。抽取文本包含式 (1)，但公式符号还未对照原图核查。
