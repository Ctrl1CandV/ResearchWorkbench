## 1. 本轮优先原则

网站是用户自己的学习读物。展示清楚、内容充实、看得懂，是取舍依据。首页帮助选择下一步，正文负责讲清知识。

用户本轮关于展示的要求优先于旧计划中的固定展示安排。旧文档中的“四区”“十个节点有详解”“桌面图文并列”“首页常显核查日期”等，不作为本轮必须延续的设计。保留数据不等于必须继续在首页展开。

抓取时间、核查时间、授权历史、内部版本与验收术语退出全站读者可见正文。记录可留在数据字段与内部审计材料中。论文正常展示发表年份、期刊或会议、标题与原文入口；预印本身份、真正影响理解的证据限制仍简短呈现。不能拿抓取或核查日期冒充发表时间；年份缺失时先保留缺失，不从核查日期推断。简报期次日期属于内容期次，可以保留并明确标成期次。

## 2. 当前实现与问题根因

项目采用原生 JavaScript、CSS 与 hash 路由，内容由 library-content.js 聚合 content/ 下的模块；没有第三方运行时依赖。library.js 同时承担页面渲染与路由；notes.js 保存本机阅读记录；guidance.js 管理独立的导学覆盖层；server.mjs/discovery.mjs 提供本机服务及论文登记发现。

本轮重点阅读了首页、地图、节点数据、样式与相关测试。以下结论来自静态代码和用户提供的截图，未重新运行浏览器验收。

| 问题 | 当前原因 | 调整方向 |
|---|---|---|
| 首页内容杂、重复 | 主推荐、精选、方向简介、知识脉络和入口之间有重复说明，维护/检索解释占据篇幅 | 保留原区块和有用内容，去重、缩短冗长说明，减负约 30% |
| 图和知识正文抢空间 | SVG 与长篇节点详情固定并排，详情栏挤压图形 | 保留可点击 SVG 图；详情移到点击后打开的第二层页面 |
| 图形排版不清晰 | 节点和连线密度、间距、标题字号及画布比例不合适 | 保留图形本身，主要调整桌面画布与节点布局，不换成主题卡片 |
| 页面像维护报告 | 日期和核查说明直接拼接进首页、节点来源与每条关系；有些技术名词与内部编号混入解释 | 正文讲知识，参考资料区承载出处与核查细节 |

本轮不扩展节点讲解；实施时保留当前已认可的详情正文，仅调整图形与详情间的页面层级。

## 3. 首页：沿用原结构做适度减负

用户明确否定上一版“只留推荐 + 三张入口卡”的大幅压缩。首页对照基准为本工作树修改前的已提交版本（当前 `HEAD`）；在不机械按字数删减的前提下，以减少约 30% 的冗余与视觉负担为方向，而不是重做为极简导航页。

- 保留原首页的核心区域、各块用途与有效内容：起步/在读、近期精选、知识脉络与综述、研究方向、技术学习、经典资料入口。主导航及个人阅读标记继续沿用。
- 优先删减重复入口、重复解释同一目的的前言、检索流程与维护口径、过长的副说明；不要仅因“压缩”而整块移走有学习价值的介绍或例子。
- 维持原有版面大体结构，通过区块标题、间距、信息密度和精选条目的简化提高扫读性。保留首读建议、真实在读状态、方向简介和精选内容；可去重，不能一并折叠或隐藏。
- 近期精选显示真实论文题名、发表时间和一条简短的阅读价值说明；不以 arXiv 编号充当标题，也不把检索词命中、抓取/核查流程和长摘要搬到首页。简报期次如保留，须明确标为“期次”。
- 全站其他可见时间规则不变：显示可靠的正式发表年份/刊会；预印本标清身份及首次提交时间；隐藏抓取、核查、整理时间，不能将其伪装成发表时间。资料和审计字段保留。
- 本轮只针对桌面端验收，不投入手机适配和低优先级鲁棒性/代码性质工作。

目标观感是原首页明显更整洁但仍然内容丰富，整体变化控制在微调范围，避免与既有阅读习惯断裂。

## 4. 领域地图：保留图形，节点详情进入下一层

推荐“地图概览 → 节点阅读 → 返回原位置”，继续使用 #/map 路由，可通过 node 查询参数表达当前节点。复用现有 hash 查询能力，具体接线在实施时核对。

用户明确认可“图形展示并点击看信息”的交互。不得用主题卡片替换图，也不得改写已认可的节点详情正文。此次只修正层级与排版：图形地图独占概览页；点击节点后进入独立详情页。

### 地图概览

- 保留现有 SVG 图形、节点与关系线作为地图主视图，继续支持点击节点进入详情；不可用卡片浏览替代图形。
- 将同屏详情面板移出地图概览。地图使用主内容区的充分宽度与高度，不与长篇节点讲解争夺空间。
- 保留既有节点、连线和语义；只调整画布比例、节点间距、标签尺寸和必要的间距，让图形在桌面可读，减少截断、线条交叠和无效留白。不新增学术分类或关系。
- 图例只需用短文字解释连线含义；层级文字和旧专题关系可保留为辅助/折叠内容，不抢图形主体。
- 现有六条学习路径可保留；如支持选中状态，只展开当前路径，不改变节点详情内容。
- 旧专题认识图放在底部“协作专题关系”折叠区，默认收起，保留原有内容与导学覆盖行为。

## 5. 节点正文范围：沿用当前已认可版本

用户明确表示当前节点详情页的信息展示“好了一些”，本轮不用动。因此不系统重写 20 个节点，也不改写现有讲解、增补统一模板或扩展内容。只允许为图形节点点击、详情打开与返回地图所需的最小链接/路由衔接；若发现明显且直接影响理解的错误，先列出具体内容再处理，不借此扩张改稿范围。

目标覆盖全部 20 个节点。先补符号与搜索、统计学习、深度学习、注意力与 Transformer，再补其余没有 guide 的节点，并清理已有 10 个 guide 中的行话与重复句。已有 guide 也要按同一可读性标准检查。

每节按需要用四到六个短段落解释：旧方法遇到什么困难 → 新方法具体改变了什么 → 一个贯穿例子 → 常见混淆或局限 → 与相邻知识和研究方向的关系。结构可以有不同篇幅，不设统一字数配额。

新名词第一次出现就解释；不以“可微函数、反向传播、表示”连续堆叠替代讲解。具体论文结论仍需实际证据；教学例子集中注明为说明性例子，不在每段重复核查声明。来源不足以支持机制或结果时补查原始资料，不能把常识扩写冒充论文已核结论。

“深度学习”的讲解语气示例（教学草稿，实施时核对来源并扩成完整小节）：

> 假设要让程序识别照片里有没有猫。一种传统做法是先由人设计可供判断的特征，比如轮廓、颜色分布或纹理，再让分类器学习这些特征和“有猫”之间的关系。难点在于：换了角度、光照或背景，原先设计的特征未必仍然有效。
>
> 深度学习把学习特征也放进训练过程。图片经过多层计算，每一层把前一层的结果重新组合，最后给出预测。训练时，程序比较预测与正确答案，再把误差传回各层，调整参与计算的参数。“表示”就是这些中间结果——它们把原始像素变成更便于完成任务的信息。
>
> 以常见的图像卷积网络为例，靠近输入的层往往对局部边缘或纹理有响应，后面的层可以组合更复杂的形状和部件，帮助区分物体。这是理解层次特征的一种方式，并不是每层都被人工指定了“找胡须”或“找猫耳朵”的职责。
>
> 卷积和循环则是两种组织计算的方式。卷积在图像的不同位置复用局部计算，适合利用像素之间的邻近关系；循环网络按顺序接收输入，并用一个不断更新的内部状态保留此前的信息。“深度学习”是更大的方法范围，不等于其中某一种网络结构。

## 6. 实施范围与验收

实施文件优先限于 public/library.js（首页微调、原图形地图排版、地图/详情路由衔接、读者可见时间呈现）、public/styles.css（桌面排版）、public/content/briefs.js（精选区展示所需题名/发表时间/短理由字段）及受影响的展示测试。只有在现有数据无法衔接图形节点链接时才修改 public/library-content.js；导航若已存在则不重复改 public/index.html。

现有内容模块、节点 ID、两条方向、个人记录、导学覆盖计算继续复用。不增加前端框架、图谱库、后台服务或学习管理机制。首页只做适度调整，地图保留原 SVG 主形式；全站页面一并遵循“论文发表时间可见、抓取与核查时间不进入读者界面”的时间规则。核查字段与既有审计资料保留，不误删资料。

执行顺序：本版设计复核已 GO；由单一指定实现者在现有工作区改动上延续；最后桌面实看首页、地图和详情页。全站时间呈现的必要断言也随实现更新，不为满足过时测试恢复抓取/核查日期。

验收以用户可见效果为主：

- 首页仍保留原主要区域与有效信息，视觉更清楚；减负约 30%，不是极简导航页。

- 点击图形节点进入现有详情页，返回后能继续看图；详情正文不被重写。
- 全站读者界面的论文发表年份清楚可见（有可靠数据时）；抓取/核查时间不显示，也没有错误地拿它们当发表年份；简报期次日期仍标作期次；示例仍清楚标明；原始核查数据与本人记录可继续访问。
