# 验收与证据

版本：v1.0 · 2026-10-04，布局设计冻结；执行范围修订 A1 见 [REVIEW](REVIEW.md)。本文件给出实施出口，不代表这些产品验收已经执行。

## 1. 判定方式

每项记录 `通过 / 失败 / 未执行 / 不适用`，不适用须说明哪页无此数据。区分实现者自检、自动测试、真实浏览器交互、视觉复核、独立审查与用户认可；一类证据不能替代另一类。

优先级：P0 为记录/资料破坏、越权上传或存储协议破坏；P1 为主要阅读/路由不可用、正文丢失、来源身份失真；P2 为违反冻结布局、明显不可读或关键交互无法使用；均阻断相关门槛。P3 为不影响上述规格的细微装饰偏差，可在明确记录并经主会话接受后后续处理。视觉失败不能因“只是 CSS”降级。

移动图默认列表需要使用新 session 夹具；已有 session 的手动图选择按真实状态检查。不要清用户 storage 取得“干净截图”。

## 4. 回归命令与检查分层

W0 先运行现有基线。阶段检查按受影响模块执行，W6 最终完整执行：

```powershell
npm test
npm run validate:surveys
node --check public/library.js
node --check public/surveys.js
node --check public/survey-graph.js
git diff --check
```

测试新增关注内容映射完整/坏配置回退、context来路、无heading宽度接缝、状态清理、非保存动作零写入等行为。原渲染结构的断言若因授权布局改动需要更新，应说明被替代的行为和新保证，不能单纯删除失败断言。

字段保全比较从公开内容模块取当前原始数据，忽略项仅为 W1 的新顶层 block id 与 readingLayout；旧 nested ID、文字和其他字段不在忽略范围。生效库覆盖行为另做现有导学回归，不能拿静态库保全代替覆盖层有效。

视觉复核必须看实际图片和运行页面：页首、正文中部、表/图、来源展开、页尾。DOM或axe类检查（如现有工具具备）只作补充，不代替可读性判断。

## 7. 最终展示与放行

向用户展示正式代表导读，以及首页、图谱、路线、论文库的代表画面和可打开入口；说明与 Demo 的功能性差异及仍待核查项。用户最终认可和独立审查分别记录。

通过标准是内容完整、真实交互稳定、视觉规格得到实际还原；不能仅靠测试数、文件数或“全站统一颜色”宣布完成。工具不足的核查项保持未执行，补齐证据后才能放行其相关门槛。
