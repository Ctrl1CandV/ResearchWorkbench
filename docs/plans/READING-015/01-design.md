# 设计决策与范围

版本：v1.0 · 2026-10-04，设计冻结。与本包 README 配套阅读。

## 1. 读者任务与目标

读者主要在桌面上连续阅读中文导读，随后查论文、比较研究路线或回到综述图谱。内容组织应当帮助读者回答：现在读什么、这段解释了什么、依据在哪里、下一步去哪里。移动端作为完整的辅助阅读入口，不用缩字和隐藏内容换取适配。

本轮要达到三个结果：

- 阅读页有稳定的行长、清楚的章节和靠近内容的来源，辅助导航让位于正文。
- 图谱里的章节和关系能直接辨认，选择内容后能进入完整讲解并返回原图。
- 首页、路线、书库和阅读页具有同一套字体、颜色与交互语言，同时按各自任务安排空间。

## 2. 证据、用户偏好和设计判断

| 类型 | 依据 | 对设计的影响 |
|---|---|---|
| 用户认可 | 2026-10-04：“你的 demo 非常好” | 冻结暖纸底、深青强调、宋体标题、连续正文、右侧辅助的阅读方向 |
| 实际观察 | 1440px 下 ACL `survey-scope` 正文只有 220px 宽，大面积右侧留白 | 布局不能依赖可隐藏目录在 Grid 中占位；必须验收无标题单元 |
| 源码确认 | `.survey-reader-layout` 采用 `220px 760px` 两列；无按钮目录被 CSS 隐藏 | 使用具名区域，或显式切换单栏；正文永远绑定主区域 |
| 实际观察 | 1440px 下整篇综述图节点偏小，最右主题需要横滚 | 在完整画布模式中给图足够空间，不以缩放文字迁就预览栏 |
| 实际观察 | 当前材料将多个导读说明和举例放在正文前 | 调整信息归属和读序；例子与边界保留在相关章节 |
| 设计判断 | 首页、图谱、书库尚无这一轮完整新样稿 | 页面结构按本包规格实施代表页后再做视觉放行，不声称已被用户逐页认可 |

视觉参考实际查看了 Distill 的 [Communicating with Interactive Articles](https://distill.pub/2020/communicating-with-interactive-articles/)：借鉴标题、导语、正文、图注的尺度关系，以及图与文字解释的紧邻。参考为英文长文；本项目中文排版、颜色、导航和内容模型独立设计。没有复制参考站资产。

## 3. 冻结的决定

| 编号 | 决定 | 实施中的含义 |
|---|---|---|
| D01 | 暖纸底 + 墨绿色主文 + 深青动作色 + 少量赭色旁注 | 使用 02 中的语义变量，不逐页临时配色 |
| D02 | 宋体负责文章和章节标题，黑体负责正文与操作 | 禁止把中文正文全部改成细宋体或只改拉丁字体 |
| D03 | 正文连续展开，章节间通过空间与细线形成节奏 | 主论证不切成等权小卡片；正文默认不折叠 |
| D04 | 阅读页取消固定全高左侧导航，保留顶栏全站入口 | 阅读只保留正文 + 一处辅助栏，避免三栏挤压 |
| D05 | 图谱页面将主要空间交给画布 | 1440 下预览移到图下；更宽且画布足够时才并排 |
| D06 | 内容事实与来源保留，展示字段可作受限增补 | 无批量文案改写、无来源升档、无论文数量扩充 |
| D07 | 先还原代表导读，再迁移其他内容形态 | 未通过代表页不得借“已统一 CSS”进入全站完成状态 |
| D08 | 尺寸变化、字号和专注模式不重建表单 DOM | 不丢未保存笔记、搜索输入、展开状态与当前对象 |
| D09 | 视图设置仅存在当前页面会话的内存中 | 不增加本人记录字段，不初始化新持久化键 |
| D10 | 同内容、同视口的真实截图是视觉放行证据 | 不能拿另一篇短文或原型截图证明正式渲染已达标 |

本包优先保留 Demo 的阅读气质。全站菜单、完整来源、真实路线和论文记录补入产品后，允许与 Demo 产生功能导致的高度差；必须按 06 解释差异，而不是无条件按像素复刻。

## 4. 范围与页面分类

所有旧 hash 入口继续可达，按三类空间结构组织：

| 模式 | 页面 | 主对象与空间 |
|---|---|---|
| 找内容 | 首页、方向、路线、论文库、经典、技术路线、精选、导学 | 顶部导航；列表、步骤或连续分组，根据任务安排 |
| 看关系 | 综述书架、单篇脉络图、领域图总览 | 紧凑顶栏；宽画布或同源列表；选中说明紧邻 |
| 连续阅读 | 论文、材料、综述单元、领域图节点讲解 | 紧凑顶栏；居中正文；右侧目录和设置；窄屏展开导航 |

技术路线的 `?unit=` 当前是定位某单元并保留全路线内容，不改成只显示单元的独立新页面。技术详情可复用阅读排版，但保持“路线内连续单元”的行为。

每日精选维持既有暂停/历史与手动发现状态，只进行必要的视觉适配。导学页保留完整预览、确认、撤销与错误信息，优先兼容而非重做流程。

## 5. 公共导航

- 顶栏保留品牌、七个主栏目及方向入口。桌面找内容页展示横向栏目，阅读/图谱页用明确的“栏目”展开按钮；移动端统一为展开菜单。
- 菜单在页面流中展开，避免遮住正文和额外弹层焦点陷阱。Escape 关闭并返回触发按钮。
- 方向快捷入口保留两条 active 的名称和链接；长名称可以换行。导学和领域地图保留现有次级入口，不变成首页主动作。
- 面包屑描述真实来路：没有显式路线的深链不假定属于主方向；回到路线必须带回实际 track/step。
- 全站导航和正文目录使用不同名称与层级；选中栏目是导航状态，目录当前项是阅读位置。
- 同一页面只有一个可聚焦的主导航集合和一个当前可见目录，不用重复 ID 或同时可聚焦的桌面/手机副本。

## 6. 内容迁移的规则

原始内容继续来自 `LIBRARY`、生效覆盖层和 `SURVEYS`。产品不得依赖 demos 或 docs 下的内容快照。正文、表格、符号解释、例子、实验条件、限制与自检全部保留。

允许迁移的信息只有展示位置与分组：

| 原信息 | 新归属 | 不允许的处理 |
|---|---|---|
| learner.gist / value | 导语附近或相关第一章的阅读背景 | 只留一句结论而删除完整说明 |
| learner.intent | 读后自问与末尾掌握目标 | 页面打开后自动标已掌握 |
| readingActions.preserve | 阅读目标的简明入口 + 可展开完整理由 | 必读定位彻底藏到来源区 |
| readingActions.explain | 相应正文或举例章节 | 把编辑例子标成论文实验 |
| readingActions.skip | “本次先跳过”的按需说明 | 删除字段或把暂缓条目标为已学 |
| 正文与局部 source | 连续章节 + 相邻来源入口 | 汇总来源后丢掉段落对应关系 |
| 完整 coverage | 明确的常显范围摘要 + 可展开详情 | partial 变 complete；待核内容靠视觉去掉警示 |
| 本人记录 | 正文后独立记录区域 | 合并到覆盖范围或增加自动状态写入 |

“折叠”只适用于回查与辅助解释；决定结论是否可信的限制必须在相关内容附近常显。标题或词语修改需要逐项内容复核，不纳入默认实施范围。

## 7. 代表材料的稳定分组

Demo 按数组下标分组不适合产品。仅为 `mat-cross-harness-map` 增加可选的展示描述：原正文顶层块增补稳定 `id`，材料增补 `readingLayout`。文字、spans、表格行、来源与既有实体 ID 不变。

| 新块 ID | 现有内容 | 展示位置 |
|---|---|---|
| scene-context | “先把场景说清”段落 | scene 章节 |
| collaboration-mechanisms | “机制是可组合的”段落 | mechanisms 章节 |
| information-representation | “表示是机制内部的选择”段落 | mechanisms 章节 |
| four-layer-comparison | 四层比较表 | 正文前概念图 + 可展开同源比较表 |
| budget-accounting | “预算要记两本账”段落 | budget 章节 |
| handoff-example | “一个中性例子”段落 | examples 章节 |
| research-question | 原末尾 callout | takeaway 章节，保留原标题与全文 |

`readingLayout.sections` 记录稳定章节 ID、展示标题及 blockIds；`figure.blockId` 指向比较表，`figure.targets` 记录行与章节的跳转关系。examples 章节接续完整 `readingActions.explain`，其余行动和掌握目标由统一组件呈现一次。该描述只作展示配置，不写入导学白名单或个人记录。

校验要求：引用可解析、章节 ID 不重复、每个正文块有展示位置、不存在静默遗漏。缺配置或配置失效时渲染原有完整正文和原表格；不凭数组位置猜关系，也不拒绝显示已存在的正文。失效原因须进开发诊断，不能给普通读者显示内部配置术语。

其他四篇材料继续使用实际 sections；没有 sections 的材料用真实的“正文”及阅读目标/来源目录，不凭空拆出五章。首轮不扩充一个通用内容编排平台。

## 8. 排除项与变更规则

不改方向集合、科研事实、来源覆盖和本人状态；不接入新后端、框架、字体 CDN 或账号；不改插件、private/、.grad/、密钥或 server 的安全白名单。首轮只在已有前端模块内实现。

需要修改数据事实、增加持久化协议、修改 query 白名单或更换上述空间模式时，应先修订本包、记录理由并复审。不能以“实施时更方便”为理由变更设计。新增技术依赖或公开部署须另有用户授权。
