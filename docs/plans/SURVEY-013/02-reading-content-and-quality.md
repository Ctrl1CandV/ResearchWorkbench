# 阅读单元、信息密度与质量标准

依赖：[01](01-discovery-and-fulltext.md)。本文件约束内容生产；它不是统一提示词一键生成质量保证。

## 1. 从“摘要卡”改为“可独立读懂的阅读单元”

地图节点只放标题、一个定位句和必要状态。点击后进入正文；正文长度由问题复杂度决定。不要把摘要、正文和证据塞进同一张小卡，更不能为了卡片整齐删掉论证。

每篇综述应有以下三层内容：

| 层 | 回答的问题 | 典型呈现 |
|---|---|---|
| 文章概览 | 这篇解决什么认知问题，覆盖什么，为什么选它 | 几段导读、原文范围、主要结构、推荐入口 |
| 阅读单元 | 一个分支/分类/比较具体是什么意思，与其他部分怎样衔接 | 连贯讲解、对照表、图解、必要公式、例子与限制 |
| 深入与回查 | 原作者怎样说明，代表文献是什么，有哪些细节可继续读 | 精确原文链接、参考条目、延伸推导、出处说明 |

阅读单元可以合并连续的小节，也可以将很长的一节拆为多个主题，但必须保持来源节到单元的映射。不能把“章节号齐全”当成全部内容都讲到了。代表工作的长列表可以折叠或作为附表保留，不把主要方法差异一起折叠掉。

## 2. 信息应该怎样写

建议以“问题 → 解释 → 例子/对照 → 条件与边界 → 与下一部分的关系”组织阅读，不要求每页出现五个一样的标题。

- **定义/背景单元**：概念是什么，不是什么；它为什么出现；与用户已知内容怎样衔接。
- **分类单元**：作者按什么维度分类；各类别的共同点与差异；是否互斥、是否可组合；难以归类的情况。不能只罗列术语。
- **方法分支单元**：输入、关键步骤、结果是什么；为什么采用这种方式；代表工作用于说明什么；代价和失败条件是什么。
- **比较/评测单元**：比较对象、任务、指标、条件和范围；是否真能横向比；表格中最值得看的区别；不能从论文被综述列出就推出它最强。
- **开放问题单元**：作者在何时认为有什么缺口；已有证据到哪里；编辑新增疑问单独标识；与当前课题的联系放收尾，不挤占原文主题。

第一段直接讲清本单元的中心问题。首次用到专业词时就解释，符号在公式附近定义。段落之间要有因果或比较关系，避免连续列出“核心机制、关键洞察、范式跃迁”等空标题。不要要求每页必须有某个图或表；只有关系/比较确实需要时才用。

**篇幅不设硬上限或最低字数。** 目录预览通常一两句；正文可以数屏，长单元按小标题分段。短是结果，不是压缩目标。首期样稿要包含一页分类、一页机制、一页评测/比较，用真实不同的材料检验结构，而非同模板换名。

## 3. 必须保住的信息

提取稿与最终讲解之间建立逐单元核对表：

| 原文信息 | 可以怎样整理 | 不能怎样丢失 |
|---|---|---|
| 核心定义与适用范围 | 用自己的话解释，术语保留原名 | 去掉限定语后变成普遍事实 |
| 分类维度与边界 | 结构图、矩阵、边界例子 | 把不同维度误排成互斥选项 |
| 方法差异与机制 | 分步骤说明或同例对照 | 只剩“提升效率/提高效果” |
| 关键证据/反例 | 图表讲解、带条件的结果句 | 只保留最显眼的正向数字 |
| 局限与争议 | 与结论相邻呈现 | 全部移到文末笼统免责声明 |
| 代表文献与出处 | 折叠附表、准确链接 | 声称已读被引全文，实际上只读综述 |
| 非核心枚举 | 折叠清单并标范围 | 无标记删掉整类分支 |

这张表服务信息保留，不强制逐句翻译。原文重复叙述可合并，原创讲解可以更容易理解；同一信息在多个章节出现时可链接，不能因去重丢掉新增条件。

## 4. 四类声音与出处

数据层记录每块的性质，界面只在必要处标识：

- `source-explanation`：对这篇综述的转述，附该版本的节/页/图表定位。
- `teaching-example`：编辑自编例子，段前一次说明，不能伪装作者实验。
- `editorial-connection`：与当前研究路线或另一文献的联系，标“阅读联系/编辑比较”，证据链接两端。
- `update`：综述发表后的补充，单独来源与时间，不混入原作者结论。

出处跟随论点、段落或表格；引用不同证据的长段应拆开。只在页末列一篇论文不够。自然语言的“某节”必须真的对应这个版本，HTML 锚点未核实时先给节标题+原文入口，不能伪造 URL fragment。

标题/刊会/年份留在概览；正文只保留必要的版本、时点和限制。核查编号、运行日志、抓取时间放内部报告或来源详情，不把网站写成审计报告。

## 5. 阅读顺序与“需要看多少原文”

同时保留“作者目录”和“建议读法”两个入口。默认建议读法通常从问题、分类主图和核心概念出发，再读分支与比较；具体由文章决定。任何重排都附一句理由，不把顺序说成唯一先修关系。

每一站包含：要回答的问题、实际学习单元、对应原文位置、为什么在这里读、如何进入下一站。顺序使用单元 ID，不依赖数组下标。

继续复用三类阅读动作，但改变呈现语气：

- **自己看原文**：分类图、关键定义、关键对照表等确实值得亲自看的位置，告诉用户看什么。
- **先读站内讲解**：本页有足够解释；原文随时可查，不能只有“建议看 §X”。
- **暂不展开**：对当前目标非必要的细枝末节，保留入口并解释原因。

这是给用户的阅读安排。Agent 完整处理综述时不能因为推荐用户跳过就不读该节。用户可以只读整理稿；它不自动等于读过原论文，更不自动写入掌握记录。

## 6. 一段实际的写作样例

样例用于标定解释的清晰程度，**不是已完成的整篇综述卡**。本轮仅核对 [2404.13501v1 §5.3](https://arxiv.org/html/2404.13501v1) 的文字；以下代码任务情境是原创教学例子，不是该综述报告的实验。不在本例复述代表系统的未经逐篇核验结果。

### 记忆管理：留下历史以后，还要怎样整理它？

这篇综述把记忆操作分成写入、管理和读取。写入决定保存什么，管理处理已经保存的信息，读取则为当前任务取出相关信息。作者在管理部分讨论了反思、合并与遗忘等处理方式。这些是理解本节的原文依据；下面用一个代码任务说明它们的区别。

假设你让 Agent 修复一个缓存错误。第一次，它发现“测试在 Windows 上失败”；第二次，它补充“失败发生在路径包含空格时”；第三次，它尝试调整引号，但测试仍未通过。如果只是把三句话全部存起来，后来的 Agent 至少能看见过程。然而，当记录积累到几十轮，同一问题会出现许多重复表述，而且“尝试过”很容易被误读为“已经解决”。

**合并**可以把重复描述整理成一条更易查找的记录，同时保留测试日志的入口。例如：“Windows、路径含空格时复现；调整引号未修复。”这里缩短的是重复措辞，不能顺手删掉“仍失败”，也不能将只在一个环境里出现的现象扩大为所有环境都失败。

**反思式整理**进一步提出可能跨任务复用的经验，例如“处理路径时要分别检查参数传递和文件定位”。这比一条运行日志更抽象，也因此需要更谨慎：一次失败只提供线索，不能据此断言所有路径问题都由这两个原因造成。在阅读相关系统时，要分清保存下来的到底是观测事实，还是由观测归纳出的建议。

**遗忘**涉及哪些记录不再留在活跃记忆中。一个编辑上可考虑的做法是将重复中间输出移出主记录，仍让原始日志可追查；这只是本例的设计选择。若删掉了唯一的反例，下一次接手可能重新尝试已经失败的办法。由此可见，记忆变短并不自动说明它更有用。

| 本例里的处理 | 保留后的信息 | 容易出错的地方 |
|---|---|---|
| 合并重复记录 | 同一故障的条件与已失败尝试 | 条件或否定词被删掉 |
| 提炼经验 | 可供下次检查的建议 | 把一次观察写成普遍规律 |
| 移出低价值记录 | 活跃内容更容易浏览 | 原始证据随之无法回查 |

读完这部分，再看“读取”：即使信息保存得很完整，当前任务也未必会取到它。你可以带着一个问题继续——一条重要的失败记录，怎样才能在下一次需要时被找到？这里提出的是阅读问题，不是在宣称某种检索策略已经更好。

原文回查：§5.3.1–§5.3.3；本文尚未讲解该节完整代表工作和 Table 3，正式制作时须补齐或明确转入相邻单元。与“跨 harness”的联系属于编辑引导，不是原文的实验结论。

### 为什么这个例子更接近目标

它用一条具体情境贯穿概念、操作和风险，保留“信息条件、事实与推测、处理与获取”的区别。它没有以固定字数认证质量，也没有靠“创新、重要、提升”等句子填满页面。正式页面还应在需要处放原文分类/比较及实际代表工作，而不把这个教学例子复制成所有单元的正文。

## 7. 质量门槛与检查办法

首期以真实试读和回查为准，不以模型自评分、标题数、字数或“字段都不为空”验收。

**来源检查**：逐条核对核心定义、分类、数字、否定/限制和图表解读。文章级与单元级版本一致；无正文支持的内容不能伪装原文事实。引用存在和引用支持这句话是两个检查。

**覆盖检查**：全文清单里每个正文节、必要附录和关键图表都有处置；各分支的区分依据没有遗漏；未覆盖部分可定位。核心节缺失时不能发布为完整导读。

**试读检查**：审查者先只读讲解，回答以下问题，再对照原文核验答案：

1. 这个部分解决什么问题？为什么引入这组概念？
2. 作者按什么标准分支？最容易混淆的两类怎样区分？
3. 至少一种具体做法怎样工作？在哪些条件下可能不适用？
4. 本节与前后两节是什么关系？哪些关系只是编辑建议？
5. 想核查一个关键论点，能否直接找到正确原文位置？

答不出来时定位缺失的解释或条件，不只要求“再写长一点”。每个问题是否适用于该类单元由审查者说明；评测页重点替换为任务、指标、比较设置与外推边界。

**表现检查**：先读本篇一个机制单元，再读不同类型的分类或评测单元。表格必须真在比较、图必须真在解释关系；正文常显，辅助证据可展开；不用大量折叠按钮拆碎阅读。

**发布阻断项**：虚构文献或出处、把部分正文标全文、作者分类与编辑分类混淆、核心反例/条件遗漏、讲解只有术语清单、必要图表不可读且未说明。表面文字流畅不能抵消这些问题。

保留首次样板的审查问题与修改前后对照，形成小型质量样例集。以后新 Agent 先看这个样例集，再制作新篇，避免每次重新解释“高质量”。

## 8. 给生产 Agent 的写作约束

```text
先读指定版本的全文清单、逐节提取稿和原文，不只读上一个模型的摘要。
把本单元需要读者理解的问题列清楚，再按其逻辑写连贯中文。
保留原文的分类依据、方法差异、条件、反例与限制；不能按固定字数压短。
每个具体学术主张能回到正确来源。自编例子和课题联系另作标识。
对定义、分类、机制、比较、评测使用适合内容的结构，不机械填同一模板。
输出正文、来源引用、原文覆盖映射、与相邻单元的关系、尚未解决的问题。
最后列出哪些原文信息被合并、折叠或未展开，以及理由；此表供审查，不进主正文。
```
