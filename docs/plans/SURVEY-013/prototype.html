留下历史以后，
还要怎样整理它？

保存下来，并不意味着以后就容易用对。

这篇综述把记忆操作分成写入、管理和读取。写入决定保存什么，管理处理已经保存的信息，读取则为当前任务取出相关信息。作者在管理部分讨论了反思、合并与遗忘等处理方式。原文 §5.3 ↗

下面的代码任务是编辑自编的教学例子，不是该综述报告的实验。

假设 Agent 正在修复缓存错误。第一轮发现测试在 Windows 上失败；第二轮发现失败发生在路径包含空格时；第三轮调整了引号，但测试仍未通过。全部保存下来能留下过程，但几十轮以后，同一问题会出现许多重复描述，“尝试过”也容易被误读成“已经解决”。

合并措辞，不能合并掉条件

把三条记录整理成“Windows、路径含空格时复现；调整引号未修复”，可以去掉重复，却仍保留复现条件和失败结果。如果只留下“修复了引号问题”，记录虽然更短，含义已经变了。

提炼经验，需要保留它的来路

我们也可以从过程里提出下次检查的建议，例如分别检查参数传递和文件定位。建议比日志更抽象，但一次失败只提供线索。后来的读者需要知道：这里保存的是一次观测，还是由观测归纳出的经验。

处理方式保留下什么要防止丢掉什么
合并同一故障与已失败尝试复现条件、否定结论
提炼经验可供下次检查的建议证据与适用边界
移出活跃记录容易浏览的主要内容唯一反例和原始出处

接下来，关心它能否被找到

本例可以选择把重复中间输出移出主记录，同时留下日志入口。若唯一的失败证据也被删掉，接手者可能再次走进同一条死路。整理之后还要看读取：重要的信息是否能在下一次需要时被找到？
