# 检索、选文与完整阅读

依赖：[总设计](README.md)。本文件是建议流程，不是本轮已完成的检索/全文阅读记录。

## 1. 输入与最小结果

支持三类输入：领域描述；一组关键词；明确论文（标题/DOI/arXiv/URL/本地 PDF）。已给论文则直接确认身份和版本，不强制先检索另外十篇。只有标题且身份有歧义时才询问；一般的主题宽泛问题先给一个合理范围及推荐。

读取背景时使用用户已明确提供的信息：机器学习、深度学习与 Transformer 基础，论文经验少。此信息用于解释与排序，不生成掌握分数，也不写入个人配置。用户想了解新领域，不等于已改变研究方向。

生产请求至少记录：输入原话、主题、想解答的问题、已有背景、指定文章或版本、范围与排除项、语言、运行日期。默认输出：**1 篇主读 + 至多 2 篇互补备选**，每篇写选择理由、补什么、不覆盖什么、实际材料可得性。不给新生一长串让其自行审稿。

## 2. 如何搜索到合适的综述

### 2.1 拆词与检索轮次

先把自然语言拆为对象、机制、目的三个词组，保留同义词与邻近表述。例如当前主方向的综述检索，不能只搜少见的 `cross-harness`：

| 词组 | 可替换表达 | 用途 |
|---|---|---|
| 对象 | LLM agent / language agent / multi-agent system | 与传统 MAS 作区分，但保留必要概念前史 |
| 机制 | communication / collaboration / coordination / memory / context sharing | 分别搜索，避免把所有词 AND 后漏掉综述 |
| 文献类型 | survey / review / taxonomy / systematic literature review | 标题含词只是候选，不直接判为综述 |
| 范围线索 | heterogeneous / interoperability / software engineering | 第二轮收窄；不是每篇都要含这些词 |

可复制的网页检索示例（不是已执行结果）：

```text
"large language model" "multi-agent" survey communication
"LLM agents" memory survey taxonomy
"multi-agent collaboration" review heterogeneous
site:dl.acm.org "agent" "survey" "communication"
site:aclanthology.org "multi-agent" "survey"
```

不同数据库的布尔语法不同；执行器应分别构造查询，保存实际发出的参数，不把上述字符串原样塞进每个 API。关键词搜不到时先扩大机制词，不直接以“不存在综述”结束。

建议三轮：广域发现 → 查刊会/正式版本与全文 → 从最有价值的候选做一次参考文献和被引追踪。先内部检查约 10–20 篇候选，数量随结果调整；已有两轮未找到新的互补视角时停止扩搜。用户侧只保留少量推荐。它是可复查的学习选文，不宣称达到系统综述的穷尽检索标准。

### 2.2 数据源分工

- Semantic Scholar / OpenAlex：候选发现、引用关系、引用量、开放版本线索。能力依据见 [Semantic Scholar API](https://api.semanticscholar.org/api-docs/snippets)、[OpenAlex 数据说明](https://help.openalex.org/data/works/citations/)。接口返回的数量是该库记录，不是世界范围精确值。
- 出版方、ACL Anthology、OpenReview 对应正式记录：核验刊会、轨道、发表身份。DBLP/Crossref 可交叉核对，不能只依据搜索摘要宣称录用。
- arXiv / 作者公开页面：获得具体版本全文与最新预印本。arXiv 不自动代表经过同行评审。
- Crossref：核对 DOI、正式刊名与出版时间；created/登记日期不作发表年份，见[日期过滤定义](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/)。
- CCF 标签仅当确有必要展示时查当版官方目录并记录版本，会议、期刊与轨道分别核对；不默认 Findings、workshop 继承主会等级。

凭据/额度/接口规则由执行当日核查，不写死“免费、免 Key、无限量”。没有 API 凭据时可用网页和官方记录完成小批检索；引用量查不到就写 null/暂缺，不捏造、不当零。

### 2.3 质量判断：不能把四个偏好当共同硬门槛

“顶刊/顶会、近几年、引用多”是优先信号，可能冲突：新文章尚未积累引用，老综述可能有成熟的分类，却遗漏近两年工作。先确认主题和内容质量，再用发表身份、更新程度和影响力做取舍。

按以下顺序给文字判据，不设未经验证的加权总分：

1. 是否回答用户要了解的领域，有没有实质分类和比较，而非论文列表或宣传性概述。
2. 范围和文献截至时间是否清楚；分类是否定义了维度，是否讨论边界、局限和未解决问题。
3. 能否获得足够完整的正文；关键图表是否读得清；其先修成本是否适合用户。
4. 刊会/评审身份与作者资料可否核实；其中的代表性不等于分类天然正确。
5. 新旧互补：通常优先近 3–4 年候选，并保留必要的旧基础综述；时效看文献覆盖截止时间，不只看文章发布年份。
6. 引用量按同一来源、相近年份和子领域观察。记录数值、查询日期和数据源；跨库数值不求平均，不把不完整的年份归一化数值伪装可靠排名。

候选表字段：标题、标识符、版本关系、领域范围、分类贡献、文献截止时间、正式刊会/预印本身份、引用数及来源/日期、全文状态、先修、主读/互补/暂缓与理由。若用户指定的综述过时仍可读；另列当前更新，不偷偷用更新版替换其指定版本。

## 3. 固定版本，先查完整性再写

一项工作可有 arXiv 多版本和正式出版版。建立同一 work 的版本关联，但**不把不同版本的章节号、图号、结果拼为一篇**。书架元数据可以说明已正式发表；正文证据必须写明实际阅读哪个版本。版本未确认时不能显示完整处理已完成。

获取顺序：合法可访问的出版社/作者 HTML 或固定版本 arXiv HTML → 可访问的原始 PDF → 现有宿主 PDF 能力 → Docling 等本地解析器。GROBID 可补学术结构与参考文献定位。扫描件按需 OCR，必须回到页面图像检查。具体工具候选见 [05](05-open-source-audit.md)。

优先复用 grad-radar 的章节获取、版本语义、真实覆盖和失败契约。它明确不做系统性检索，原默认“选节阅读”也不等于本需求“读完整篇”。项目工作流应按目录循环调用切片工具，补读所有正文节和影响主张的附录；不改插件安装文件。`reading_record.py` 不是必须接入网页的数据库，本轮不调用它初始化或改写用户 `.grad`。

### 3.1 先建立原文清单

```text
固定版本
  ├─ 正文节/子节：标题、顺序、HTML 锚点或 PDF 物理页
  ├─ 图：图号、图注、图像是否已查看、承载的论点
  ├─ 表：表号、表头/单位/脚注、是否完整
  ├─ 公式：符号、条件、是否可辨认
  ├─ 附录：是否影响主文解释
  └─ 参考文献：保留索引；不代表把被引论文全部读了一遍
```

完整阅读指综述本身，不承诺读完其中数百篇原始文献。转述被引研究时写“综述归纳/报告”；要升级为原论文事实必须单独查原文，并保留单独来源。

PDF 定位同时区分物理页和文内印刷页码；HTML 没有页码就使用章节/锚点，不根据字符数估算页码。正文实际覆盖到结论、附录和参考列表入口后再确认未截断，不能只看目录还在就判全文完整。

### 3.2 四个容易造假的状态必须拆开

`取得文件` → `正文可解析` → `Agent 实际读取并提取` → `讲解经过核对`。

下载 PDF 或解析得到很多字符，都不等于读完。每个 section/figure/table 的记录独立包含 `extracted`、`read`、`checked` 和 issue。图注可读但图片不可读，应记 `caption-only`；不是 `checked`。列表页“完整导读”是内容覆盖状态，绝不表示用户本人已读。

完整发布条件：所有正文节和必要附录有真实阅读记录；关键图表/公式已读并核对；每个来源部分都映射到阅读单元或说明性“仅作索引/无需展开”；不存在未说明的正文缺口。致谢、参考列表不必逐条制作教学卡，但要记清处理方式。章节映射齐全不等于信息完整，还要核对单元内的分类、限制和比较是否遗漏。

若受限，输出可用的部分讲解和缺口清单，界面说明“部分导读：缺第 X 节/图 Y”。不能只把章节隐藏就标完成。没有全文最多提供选文介绍；它不进入“完整综述阅读”数量。

## 4. 分段读全的具体方法

1. 第一次读摘要、引言、完整目录、分类图和结论，记录作者试图回答的问题、组织逻辑及自述范围。这一步只建立骨架。
2. 按章节边界逐节读，不以固定 token 切块直接生成最终摘要。过长章节分为有重叠上下文的小段，每段携带文章版本、祖先标题、术语和相邻段标识。
3. 各段提取：定义、分类及标准、机制、代表工作、比较维度、证据、成立条件、限制、图表引用、待核问题。原始提取稿保留，不只保留二次摘要。
4. 合并时核对共用术语和跨节引用；同名概念在不同作者体系中含义不同，不强行合并。每条主要论点保留来源锚点。
5. 对照整篇目录与关键图表，查“中间章节、否定结果、附录、脚注”是否遗漏；对矛盾返回原文，不能以多数片段投票消除矛盾。
6. 完成提取后才写面向读者的教学内容与推荐顺序。最终写作者可回读原文及提取稿，不能只读上一模型的压缩总结。
7. 原文证据核查和中文试读分别执行。修订时改有问题的单元，保留版本、证据和用户笔记。

预算不足时分批继续，保存完成范围和下一节；减少本轮文章数量或推迟完成，不要求“整篇压到 2k token”。对本项目而言，输出紧凑的索引和充分的正文可以同时成立。

## 5. 生产文件与结果记录

建议原始 PDF、提取全文及临时运行输出放 `private/surveys/<work-id>/<version>/`，沿用已有忽略规则。非公开材料不对外上传；必要云解析须单独确认数据及目的地。

可进入仓库的原创讲解、公开来源定位与生产报告放 `docs/research/surveys/<survey-id>/`；发布内容进入指定 public 数据模块。公开文件不包含个人绝对路径、私人请求原话或 PDF 全文。原图使用按授权处理，默认链接原图或绘制注明“编辑重绘”的示意，不直接打包整篇 PDF。

每轮交付报告区分：检索了哪些渠道；实际获取了哪个版本；读到哪里；哪些内容已核对；哪些是 AI 的教学解释；哪些仍缺材料。运行日期等留在报告/详细来源中，主阅读界面不铺维护信息。
