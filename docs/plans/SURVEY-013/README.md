## 1. 这次要交付的读者体验

用户给出一个领域、几个关键词或一篇综述，Agent 找到合适的综述，读取其完整正文、关键图表与附录，制作有出处的阅读材料。网站让用户看清这篇文章如何组织问题、各部分如何关联、应按什么顺序阅读，并能在以后查到具体解释和原文位置。

版块建议命名为 **综述阅读**。最小内容单位是“一篇具有明确版本的综述及其阅读材料”，不再是脱离文章、只附泛化来源的概念点。卡片是进入讲解的入口；正文可以是完整的小节，不受卡片高度或统一字数限制。

三个结果优先：

1. 找对文章：相关、适合起步、有可靠出处，刊会声誉、发表时间和引用量有据可查。
2. 讲清内容：保留定义、分类依据、机制、对比、关键证据及限制，用连贯中文解释。
3. 能读能查：文章内有清楚的阅读路径和关系图，以后可以从多篇综述的关系进入具体章节。

这是学习引导，不是要用户读完一份几十篇课表。Agent 负责有依据地推荐，不把选文与文献质量审查推回给新生；用户可随时改主题或指定文章。

## 3. 设计取舍

**扩写原来的 20 个节点**能改善局部文字，但仍无法表达一篇综述的章节覆盖、版本和作者分类；适合维护背景导读，不足以完成这次任务。

**直接做 PDF + 聊天框**方便问问题和核对原文，但读者仍需自己发现没问到的章节，生成结果也难形成稳定阅读路线。原文入口值得保留，问答不是首期主界面。

**推荐：文章书架 + 单篇阅读空间 + 两级关系图。** 文章是组织单元；概览负责选择和定位；内容页负责完整解释；图来自同一份经过核对的结构化内容。它对当前静态内容平台的改动可控，也能承载后续多篇积累。

两级指的是图的语义层级，不是强制只允许两个页面：

```text
综述书架 / 一级图：文章 A ──补充某主题── 文章 B
                         │ 打开文章 A
单篇概览 / 二级图：定义 → 分类 → 分支 → 比较与评价
                         │ 打开一个阅读单元
阅读正文：连贯解释 + 表格/图解 + 原文定位 + 前后衔接
```

不把文章目录、概念依赖、学术关系、推荐顺序混成同一种边。原文先后顺序也不自动意味着逻辑依赖。

## 4. 生产方式与首期范围

生产在用户调用的 Agent/harness 中执行，网站负责阅读与回查。首期可在“添加综述”中填写领域/关键词/链接并复制标准任务或导出请求 JSON，交给 Agent 处理；界面明确“交给 Agent 制作”，不显示不存在的自动生成进度。直接在聊天中提出需求也完整支持。

后续如需网站一键调用模型，再单独设计任务执行、凭据和失败恢复。此次不把自动化服务建设作为阅读改造的前置，不扩 `/api/discover`，不接管 `.grad` 个人记录。

| 阶段 | 交付 | 完成的判据 |
|---|---|---|
| A：内容样板与界面设计 | 一篇综述的完整目录清点；三种不同内容单元样稿；静态界面样稿 | 独立审查实际来源与试读质量；不能只看模板字段是否齐全 |
| B：一篇纵向闭环 | 一篇全文处理完毕的综述、全部阅读单元、文章内图、连续阅读和来源跳转 | 完整性与内容质量合格；真实桌面走查通过 |
| C：可重复生产 | 用第二篇验证领域/关键词输入、元数据去重、批量章节处理及第二次入库 | 不依赖首篇硬编码，旧链接与已有材料保留 |
| D：文章间一级图 | 用实际已生产文章建立有依据的关联，至少能展示一组真实跨文章关系 | 不为了连线捏造引用、继承或“取代”关系；没有关系时可显示独立节点 |
