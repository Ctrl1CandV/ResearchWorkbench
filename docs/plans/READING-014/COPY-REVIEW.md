## 24. ACL五维章节 / 正文段落 2

修改前（196字）：

## 25. ACL五维章节 / 正文段落 3

修改前（135字）：

静态环境可以让模型根据缓存页面或历史轨迹预测下一步，易于规模化；但一次错误不会改变后续观察，因而看不到错误累积造成的连锁失败。动态环境允许行动改变世界状态，例如在容器或浏览器沙箱中持续操作，更适合暴露长任务中的状态跟踪和恢复问题。代价是运行更复杂，结果也更依赖环境实现。

修改后（166字）：

在静态环境里，可以让模型依据缓存页面或历史轨迹预测下一步，比较容易扩大评测规模。但模型预测错误时，后续观察不会随之改变，因此评测看不到错误累积引发的连锁失败。动态环境允许行动改变世界状态，例如让 Agent 在容器或浏览器沙箱中连续操作。这有助于观察长任务中的状态跟踪和错误恢复，同时也增加了运行复杂度，使结果更依赖环境的具体实现。

## 26. ACL五维章节 / 正文段落 4

修改前（141字）：

代码/终端、受限工具调用、图形界面分别要求 Agent 生成程序、遵循函数 schema，或从 DOM/视觉界面定位并操作对象。它们测到的能力并不相同。一个工具调用基准上的高分不能直接说明 Agent 会使用 GUI；一个静态 GUI 轨迹集也不能充分检验它在动态环境里的状态管理。

修改后（170字）：

代码或终端接口、受限工具调用、图形界面要求 Agent 做的事情不同。它们分别需要生成程序、遵循函数 schema，或者从 DOM 与视觉界面中定位并操作对象。比较结果时，需要考虑这些能力差别。Agent 在工具调用基准上得分高，并不足以说明它也能熟练操作 GUI；使用静态 GUI 轨迹的评测，也难以充分检查它在动态环境中管理状态的能力。

## 27. ACL五维章节 / 正文段落 5

修改前（165字）：

单元测试、目标状态匹配、答案匹配分别适用于代码产物、环境状态变更和有明确答案的问题；它们不能互相替代。作者特别提醒，二元的最终成功/失败指标很难说明 Agent 中间如何推进或失败。多次独立运行的 pass^k 可帮助观察稳定性，但任务成功本身不保证过程合规；若 Agent 通过越权或危险操作达成目标，单看成功率会奖励错误行为。

修改后（190字）：

单元测试用于检查代码产物，目标状态匹配用于检查环境是否发生了预期变化，答案匹配适用于具有明确答案的问题。这几种判据各自适用的任务不同。作者提醒，只看最终成功或失败，很难知道 Agent 在中间步骤怎样推进、又在哪里失败。多次独立运行的 pass^k 可以帮助观察稳定性，过程是否合规则需要单独检查。如果 Agent 通过越权或危险操作完成任务，只计算任务成功率就可能奖励这些行为。
