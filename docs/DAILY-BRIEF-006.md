# 每日精选工作流（2026-09-18 落盘）

目标：每个**工作日**产出一期"每日精选"，页面 `#/brief` 展示当期并保留全部历史工作日索引。

**不是自动服务**：没有定时任务、没有无人值守抓取。每个工作日由用户给 harness 发一次提示词（模板见 §5）触发完整流程；不发提示词的日子就不产出，页面如实缺日，不补写。

## 1. 工具链与边界

- 生产工具：grad-companion 插件的 **grad-radar 技能**（arXiv 每日漏斗 + 分级规则 `references/tiering.md`）。技能边界即本流程边界：只做每日定向筛选，不做系统性文献检索；不创建定时任务；"每日" = 用户调用时处理当天窗口。
- 首次初始化已完成（2026-09-18）：`.grad/config.json` 由 `radar_config.py init` 建立、validate 通过，关键词按三个已批准方向定制（代码智能体修复验证 / 可信 RAG / 图有害融合 + Agent 主干，共 14 组），分类 cs.SE/cs.CL/cs.AI/cs.LG/cs.CR，daily_caps 优先关注 1 + 可以速览 2，回看 3 天（arXiv 索引滞后 1–3 天）。`reading_profile` 留空——个人背景由用户自己填，不由工作流代写。
- `.grad/` 在 `.gitignore` 内，只留本机，不入库、不上传。去重台账 `~/.grad-radar/seen.jsonl` 跨项目共享，**seen ≠ 已读**。
- 网页只做静态展示：动态漏斗条目不进入 `papers` 内容库，不写入 v3 个人记录，不把打开链接记成任何状态。

## 2. 每日执行步骤（harness 侧）

1. 加载 grad-radar 技能，确认 `.grad/config.json` 存在且 validate 通过（缺失/损坏按技能契约 init/修正，已有文件绝不覆盖）。
2. 运行 `arxiv_fetch.py --config .grad/config.json --json`（串行，勿并行）。记录 `total_matches` / fetched / `truncated`。
3. 按 `tiering.md` 分级：理由必须 = **命中的具体信号 + 引用的原文片段**，可反驳；"启发式排序，不是质量判断"每期必带。`truncated: true` 必须写进当期口径，不称已覆盖全部新论文。
4. 内容提取深度：**优先关注**可做一次轻提取（摘要 + 引言，经 `arxiv_html.py`）；**可以速览**只依据摘要。默认不为候选获取全文。全部条目标明"正文未核对"。
5. 写当日简报 `.grad/radar/YYYY-MM-DD.md`（机器可读头部 + 人读正文 + 归档索引一句理由 + 至多一条学习建议）。**已存在默认复用，不静默覆盖**；用户要求刷新时保留旧版再更新。
6. 映射为网页一期：在 `LIBRARY.briefs` 追加 `{ id: 'brief-YYYY-MM-DD', date, scope, items }`——
   - 只收 优先关注 + 可以速览（配置上限），其余候选留在 `.grad/radar/` 归档索引；
   - `scope` 必须按 §4 的「检索/收获/边界」三段式写作；
   - 条目目标：命中库内论文用 `paperId`，否则 `source` 用 arXiv abs 页 https 链接，二者只取其一；
   - 可见文案不出现内部机器词（grad-radar、deliveredDepth 等，回归测试强制）；
   - `published` 写 arXiv 提交日期并注明"arXiv 提交"；
   - 同步更新 `contentVersion`。
7. `npm test` 全绿后才算当日完成。更新 README/SPEC 的进度记录按需。

## 3. 诚实口径（每期必须遵守）

- **缺日不自动补写**：没跑的日子页面就没有那一天；索引下方固定说明"仅列出实际产出的工作日"。**用户明确要求补历史某日时才回溯补记**：scope 写明"回溯补记"、用扩展窗口全量数据按 arXiv 提交日归位、与已展示期去重，并同步补写 `.grad/radar/` 本地文件；不冒充当日运行。
- **空窗口 ≠ 没有新论文**：先怀疑索引滞后，可 `--days 5` 扩窗重跑一次；仍空如实写。网络错误（NETWORK/RATE_LIMITED）与"没有匹配论文"分开呈现。
- **不凑数**：不足 caps 就少一些；多出来的候选降一级进归档索引，不丢弃。
- **整理日期与论文日期分开**；摘要级文本不引用摘要里的百分比数字（详见 §4 写作纪律）。
- 用户对分级有异议：按 `tiering.md` 反馈回路处理（改关键词组或记录到当期"分级调整记录"）。

## 4. 简报 scope 的固定格式（收获文本契约，2026-09-18 固化）

`scope` 是一段式纯文本，面板按既有样式渲染"整理日期 X（区别于论文发表时间）；覆盖范围：{scope}。"，**不引入新的视觉组件**。内部固定三段，段首词与顺序固定：

1. **检索：** 方法（每日漏斗 / 手工挑选 / 回溯补记）+ 窗口与检索面概况 + 命中/抓取/截断条数 + 分级取舍（各档取几篇、是否去重）。漏斗自身的数字可直写；补记期必须写"回溯补记"并说明归位与去重方式。
2. **收获：** 当日最重要的结论——哪个方向有实质命中、最值得看的一篇是什么（一句可检验的判断；原文关键句的引用放条目的 reason，不进 scope）；没有命中的方向如实点名说没有。
3. **边界：** 依据级别（摘要/引言/正文核对到何处）+ "启发式排序，不是质量判断"（漏斗期必写）+ 整理日期。

写作纪律：正文未核对一律写明"正文未核对"；摘要级文本**不引用摘要里的百分比**（与 meta.notices 同一纪律——比例改定性描述并注明"以摘要陈述为准"；设置类计数如"176 组对照""500 个决策状态"可写）；scope 全段 400 字内——抓取情况一句带过、收获是重点。条目层不变：`reason` = 具体信号 + 可反驳引用，`summary` 只写已获取材料支持的层面。

## 5. 历史工作日索引

`#/brief` 页"历史工作日"按期列出全部简报（新在前、标明本期、附条数），往期经 `#/brief/brief-YYYY-MM-DD` 直达；首页第四区自动展示最近一期前 3 条。渲染与口径由 `tests/render.test.mjs` 的简报页用例守护。
